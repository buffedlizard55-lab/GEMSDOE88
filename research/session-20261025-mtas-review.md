The documented local distance-weighted Tversky implementation uses a 300 m (3-pixel) triangular kernel, false-positive weight 0.2 and false-negative weight 0.8; see [local metric implementation](../vendor/gems57/metric.py) and the [organizer problem page for manual review](https://www.drivendata.org/competitions/306/competition-doe-gems/page/967/) (not reachable from this sandbox). For a dot set with unknown truth \(G\), write \(T\) for truth coverage, \(M\) for the sum of each predicted dot's own truth credit, \(n\) for the dot count and \(K=|G|\). Then `DTI = T / [0.8 K + 0.2 (T + n − M)]`. Removing redundant dots can reduce the denominator's false-positive component without losing much numerator, while pruning near already masked catalogue pixels can avoid wasted predictions. **Neither closeness to the known catalogue nor the subset relationship establishes that removed dots had zero credit against *hidden* faults.** A blind fault may be near a mapped fault, and aggressive thinning can lower recall; thus H33's user-reported ordering is *consistent* with the precision/coverage mechanism, not causal proof. The earlier dossier's assertions about hidden precision, perfect collar purity and a guaranteed improvement were not justified by these bytes; do not use them as facts.
