Submission gate in plain English

A GeoTIFF is not approved just because a GIS program can read it. The project automatically tests data lineage, the blocked experiment, individual-feature leakage, duplicate geometry, file values, exact grid, SHA-256 identity, and the contents of its ZIP. If any check fails or the evidence is missing, the decision is NO.

The system did not silently exempt the prior.

Exactly how an approved GeoTIFF would enter the contest

These are instructions for a future automatically approved candidate, not permission to upload MGC-88. The research ZIP here is not a workaround.

  1. Run the project validator

    From the repository: python scripts/restore_inputs.py --validation, then python scripts/validate_release.py --require-submit. Only exit code 0 together with a receipt showing ok_to_submit: true would qualify. This release returns exit code 2. The auto-check must compare against the actual pinned competition sample; our sample is an owner mirror, so organizer-side acceptance remains unconfirmed.

  2. Check the separate slot selector

    Only a candidate that clears scientific and registry promotion may be considered. The NLR official rules §3.2/§3.4 specify up to three submissions per week, but the live remaining allowance and any rule updates require the authenticated competition page; this project did not access that page. Never spend a slot merely to “see if the TIFF works.”

  3. Use the DrivenData form, not a document upload

    At the official submission page, choose an approved single-band .tif in “File to submit” (or a .zip containing that one TIFF). The TIFF must match the sample’s EPSG:32611 CRS, 100 m resolution, dimensions and affine transform, and contain only finite float32 scores in [0,1] inside the footprint. Paste the approved candidate’s unique short note into “Note (optional)” and submit once. This sandbox has no DrivenData login and cannot produce an organizer receipt.

  4. Store the organizer receipt

    Only the organizer submission page can confirm acceptance/score. Archive its submission name, timestamp, received filename, status and receipt as ORGANIZER-CONFIRMED. The project’s HOLDOUT-DTI must remain separate. The final private and expert-updated scores are different targets.
