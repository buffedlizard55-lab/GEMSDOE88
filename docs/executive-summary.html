Procedure for a future, separately authorized candidate

Submit only after every gate is green

This procedure does not authorize submission of KTH-88 or any historical TIFF. A future candidate must have its own current run card, saved-byte audit, successful holdout and leakage checks, passing uniqueness checks, and separate slot-selector authorization.

  1. Confirm the current decision and authorization

    Check the current release JSON and the candidate-specific run card. Require the current validator to pass its submit gate and confirm the separate selector has authorized a slot. A format-only pass is not enough.

  2. Use only the approved artifact

    Download the exact TIFF or one-TIFF ZIP named by the approved run card. Do not use an archived research artifact or a file whose name contains DO-NOT-SUBMIT.

  3. Sign in to the official competition portal

    Open the DrivenData submissions page using the team account. The portal and the current official rules govern upload limits and acceptance.

  4. Upload one valid raster and enter its approved metadata

    Upload one single-band GeoTIFF or a ZIP containing exactly one GeoTIFF. The TIFF must match the official sample grid (CRS, shape, and affine transform) and contain finite prediction values in [0,1]. Enter only the unique name and note from that candidate's approved run card (note ≤140 characters).

  5. Save the organizer receipt

    Archive the portal receipt. Call a score ORGANIZER-CONFIRMED only when it is copied from that receipt. Do not report holdout DTI, a public leaderboard value, or a model projection as an organizer score.

Official references retained in the repository: metric and submission-format page · competition rules · reference solution. Local preflight cannot authenticate to the portal or prove acceptance.
