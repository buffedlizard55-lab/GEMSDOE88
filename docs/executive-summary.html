How an approved GeoTIFF is submitted to DrivenData

These instructions explain the exact competition submission mechanics required by the brief. Do not upload any DO-NOT-SUBMIT research artifact unless a human selector explicitly updates the registry policy for continuous-surface priors and re-exports an approved candidate.

  1. Run the automated preflight locally

    Execute .venv/bin/python scripts/restore_inputs.py --validation followed by .venv/bin/python scripts/validate_release.py --require-submit. The automated gate requires exit code 0 and "ok_to_submit": true in docs/status.json. Under binding IR-88-01, this release returns exit code 2 and blocks upload automatically.

  2. Verify weekly slot budget with the human selector

    Per Official GEMS Prize Rules (NLR FY26-96647) and DrivenData Problem Description, teams have a strict weekly feedback submission cap, and the same single selected GeoTIFF from the Initial Prize Round ($50k) is rescored in the Final Prize Round ($250k) against expert-expanded fault labels. Never spend a weekly slot on format smoke tests.

  3. Upload on the DrivenData submissions portal

    On the authenticated DrivenData Submissions page, select the single-band float32 GeoTIFF (EPSG:32611, 3292 × 3730 width × height, 100 m pixels, values in [0, 1]) or its single-file .zip, paste the exact ≤140-character note into the optional note box so the run’s SHA-256 and method stem are traceable, and submit once.

  4. Record receipt as ORGANIZER-CONFIRMED

    After DrivenData finishes scoring, archive the exact portal timestamp, filename, and public DTI score labeled ORGANIZER-CONFIRMED — strictly separated from local HOLDOUT-DTI estimates.
