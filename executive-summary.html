Executive summary & competition submission guide

How to create, validate, and submit a prediction without confusing a research result with a competition score.

Current status: NOT READY. There is no prediction TIFF in this repository. Do not submit a file from GEMSDOE88. The required competition data, shared holdout evaluator, registry rasters, and writer are absent, so neither a unique candidate nor an improved holdout result can be established.

What the file must satisfy

The competition upload flow accepts a single-band GeoTIFF or a ZIP containing exactly one GeoTIFF. The prediction grid must match the official sample-submission raster in CRS, dimensions, and geotransform. Predictions must be finite values in the closed range [0, 1]; this project validator checks the entire grid to prevent the reported “Predicted values must be in range [0, 1]” rejection. Always review the current competition rules and official template.

Official references: problem description · data and template (login may be required) · DOE/NLR submission guidance.

Upload steps — only after a candidate is marked ready

  1. Open the competition data page and obtain the official sample_submission.tif plus authorized training data. Keep source and licence details.
  2. Run the shared, spatially blocked hide-and-recover evaluation. Withhold whole fault segments with a buffer, build catalogue-derived features only from visible segments, mask visible faults pixel-exactly, test each feature alone for leakage, and report pooled DTI with evaluator version, positive count, and 95% CI.
  3. Require the candidate to beat the current holdout best, then compare its surface against the prior registry before placement and compare final emitted dots against all registry rasters. Stop on correlation above 0.90 or if more than 70% of dots fall within 3 pixels of a registry dot set.
  4. Write a fresh single-band GeoTIFF using the official writer. Do not copy a prior submission. Use zero outside the footprint if necessary to keep all pixels finite and within [0,1], unless the official submission contract specifies otherwise.
  5. Run the format gate:
    python scripts/validate_submission.py --prediction CANDIDATE.tif --reference sample_submission.tif --report candidate-validation.json
    Proceed only if it reports PASS; this is format validation, not a score or uniqueness certificate.
  6. Create a unique name and a note of at most 140 characters that identify the hypothesis and method without claiming a projected or unconfirmed score. Preserve the output hash and validation report.
  7. On DrivenData, choose “New submission,” attach the validated TIFF (or a ZIP containing only that TIFF), enter the name/note if the form offers them, review the current rules, and submit. Save the organizer receipt. Only the receipt can support an ORGANIZER-CONFIRMED score claim.

The portal wording/fields can change. Confirm the current page and the competition's weekly submission allowance before using a slot. Do not spend a slot on an unvalidated hypothesis.
